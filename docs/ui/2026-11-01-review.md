## Scope and state

Work is on `codex/ui-refinement`, based on `36020ce`. **Local only; no deployment or production changes.** The existing green identity, Poppins/Inter typography, light/dark selection, routes, role guards and API contracts remain. Backend source, production configuration, storage and database were not changed. No dependency was added or upgraded for this work.

The user requested whole-application refinement, then rejected the initial landing sample-record panel, approved the book hero, requested restrained dynamism, and requested less green in the landing dark mode only. The final direction retains the book; public dark surfaces are charcoal with green accents, while authenticated workspaces retain their forest theme.

## Implemented

- Landing: clearer academic introduction, shared original document mark, book illustration linked to the collection entry, first-viewport primary action, compact mobile composition, accessible repository path tabs, active-section navigation, genuine submission steps, understated role descriptions and a defined closing section. Fabricated usage counters, unsupported accuracy/storage promises and dead legal placeholder links were removed. Existing university/contact information remains.
- Shared presentation: solid theme surfaces, lower shadow intensity, readable placeholders/secondary text, fewer decorative effects, consistent radii, controlled spacing, visible focus, operable scrollbars, reduced-motion support and mobile form sizing.
- Role workspaces: retained navigation and actions, named landmarks and controls, skip links, dynamic viewport shell, improved density, sidebar-aware grids, visible table overflow regions and dark-mode semantic badge contrast. Off-screen/collapsed sidebars no longer remain keyboard/screen-reader targets. Mobile drawers contain focus, close with Escape and restore their opener.
- Research records: smaller empty cover artwork, better title wrapping, keyboard access on migrated clickable cards, retained card/table choices, metadata, status and actions.
- Forms: 164 label/control associations or accessible-name insertions across the existing forms and controls. Shared authored category/search suggestions now have keyboard/ARIA behavior. Search clearing cancels pending timers/requests, and superseded suggestions cannot overwrite newer ones.
- Overlays: shared focus/scroll ownership, sensible Cancel focus for confirmations, Escape and focus restoration, and body portals for 12 specialized modal owners. Existing busy/skip/submit rules were retained.
- Upload UI: shared client check for exact 128 MiB maximum, clear MiB units/limit, long-filename wrapping, keyboard file selection, honest indeterminate processing feedback, retained metadata status/scope and complete document/reference payloads. Backend remains authoritative.
- Routing/performance: readable route titles and a useful missing-page screen. `/dashboard` resolves to the same role workspace used by the existing application rather than the obsolete generic dashboard with inactive quick actions. Protected screens, charts and PDF code load on demand.

## Static audit and intentional contracts

The installed design skill's strict audit is recorded privately under `.local/ui-premium-audit.json`. It reports **6 findings**, not a pass: 3 inactive actions in unrouted legacy student components, 1 native verification-form convention and 2 textarea-resizing conventions. The source-only legacy dashboard/bookmark components are not routed by `App.jsx` and have not been promoted into active workflows. The static report is not a substitute for browser acceptance and must not be described as a clean accessibility certification. For the configured build command, set process-local `VITE_API_BASE_URL=/api/v1` first; no production configuration file is changed by that check.
